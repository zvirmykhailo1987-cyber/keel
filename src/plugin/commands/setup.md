---
description: "Перше налаштування Keel: перевірка середовища, vault, за згодою планувальник"
argument-hint: "[шлях до vault]"
---

Налаштуй Keel для цієї людини. Кожну зміну стану роби лише після того, як людина побачить, що саме зміниться.

1. Перевір середовище:
   `sh "${CLAUDE_PLUGIN_ROOT}/hooks/run.sh" -m keel doctor`
   Звір `python`, `git`, `claude у PATH`, `sh`. Бракує Python 3.11+, git або `sh`: поясни, що встановити, і зупинись. Без `claude` Radar працює, а фонові кванти ні. `fail` у пункті `vault` тут очікуваний.

2. Спитай шлях до vault, типово `~/keel-vault`. Це тека особистих знань: Markdown і git, переживає оновлення й видалення плагіна. Якщо шлях дано в аргументі (`$ARGUMENTS`), запропонуй його. Якщо `doctor` показав інший шлях, ніж типовий, його задано в налаштуваннях плагіна: запропонуй саме його.

3. Створи vault:
   `sh "${CLAUDE_PLUGIN_ROOT}/hooks/run.sh" -m keel setup --vault "<шлях>"`

4. Попередь про `ANTHROPIC_API_KEY`, якщо `doctor` його побачив: із цим ключем звичайний `claude -p` списує кошти API, а не підписку. Фонові кванти Keel ключ прибирають, а власні скрипти людина перевіряє сама.

5. Покажи план планувальника, він нічого не міняє:
   `sh "${CLAUDE_PLUGIN_ROOT}/hooks/run.sh" -m keel autopilot schedule`
   Поясни своїми словами: яка система, як часто, що запускається, що щогодинний цикл працює без LLM, доки фон вимкнено, і як прибрати задачу (`/keel:autopilot unschedule`). Спитай, чи ставити задачу.

6. Лише після явного «так» саме на цей крок:
   `sh "${CLAUDE_PLUGIN_ROOT}/hooks/run.sh" -m keel autopilot schedule --apply`
   Без згоди не став: Radar працюватиме вручну через `/keel:radar`.

7. Фонові кванти тут не вмикай. Скажи, що це окремий вибір у `/keel:autopilot`.

8. Заверши підсумком: шлях до vault, що ввімкнено, що вимкнено. Наступний крок: `/keel:init-project` у потрібному репозиторії.
