---
description: "Чернетка ADR у vault; після рішення людини перенесення в репозиторій"
argument-hint: "<назва рішення>"
---

Підготуй ADR на тему: `$ARGUMENTS`. Для складного вибору застосуй навичку `keel:architecture` або доручи порівняння агенту `keel:architect`. Якщо агент уже дав JSON `draft_adr`, бери його.

1. Збери контекст, рішення й наслідки: і добрі, і погані. Спирайся на реальний код і дані, невідоме познач «немає даних». Значення `project` це імʼя теки репозиторію, під яким він підключений у `/keel:init-project`.

2. Подай чернетку:
   ```sh
   sh "${CLAUDE_PLUGIN_ROOT}/hooks/run.sh" -m keel propose <<'JSON'
   {"action":"draft_adr","params":{"project":"...","title":"...","context":"...","decision":"...","consequences":"..."},"why":"...","source":"...","confidence":0.9}
   JSON
   ```
   Якщо оболонка не підтримує heredoc, запиши JSON у тимчасовий файл і передай `propose --file <шлях>`.

3. Результат `executed` дає `path` відносно vault: зазвичай `projects/<проєкт>/adr-drafts/<назва>.md`. Результат `card` означає, що рушій передав питання людині: `/keel:decide`. У репозиторій чернетка не пишеться.

4. Покажи чернетку й спитай людину: прийняти, змінити чи відхилити.

5. Лише після рішення людини перенеси текст у `.keel/adr/NNNN-<назва>.md` цього репозиторію: наступний вільний номер, статус `accepted` і дата. Не комітити без прохання людини.

Рішення людини не приймаєш: статус `accepted` ставиться лише за її явним словом.
