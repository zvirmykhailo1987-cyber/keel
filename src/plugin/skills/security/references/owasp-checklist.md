# Чекліст OWASP Top 10:2025

Нумерацію й назви звірено зі сторінкою https://owasp.org/Top10/2025/ 06.11.2026. Для кожного пункту статус: перевірено чисто / знахідка / не перевірено з причиною.

## A01 Broken Access Control

- Кожен обробник із id має перевірку власника: див. `authz-secrets-supply.md`.
- Заборона за замовчуванням: новий маршрут без явного правила недоступний.
- Перевірка на сервері, а не лише в інтерфейсі.
- Масове присвоєння: користувач не може надіслати `role=admin`, `owner_id`, `price`.
- CORS не відкриває робочі дані довільному походженню разом з обліковими даними.
- SSRF у редакції 2025 віднесено сюди: серверний запит за URL користувача обмежено списком дозволених; блокуються внутрішні адреси й метадані хмари.
- Обхід шляху: файл за іменем від користувача не виходить за межі каталогу.

## A02 Security Misconfiguration

- Режим налагодження вимкнено; стек-трейси не віддаються клієнту.
- Дефолтні паролі й приклади прибрано.
- Заголовки: `Strict-Transport-Security`, `Content-Security-Policy`, `X-Content-Type-Options`.
- Панелі адміністрування й метрики не відкриті назовні.
- Сховище об'єктів і бази не публічні.

## A03 Software Supply Chain Failures

- Lockfile є в репозиторії; у CI встановлення за lockfile.
- Аудит вразливостей запущено; транзитивні залежності теж.
- Нові пакети перевірено: імʼя, власник, вік, install-скрипти.
- Екшени CI за повним SHA; права `GITHUB_TOKEN` мінімальні.
- Образи контейнерів із закріпленою версією.

## A04 Cryptographic Failures

- Трафік із TLS; чутливе поле зашифровано чи не зберігається взагалі.
- Паролі: Argon2id, scrypt чи bcrypt; жодного MD5, SHA-1 чи голого SHA-256.
- Випадковість для токенів криптографічно стійка: `secrets`, `crypto.randomBytes`, `crypto/rand`.
- Ключі не в коді, ротація можлива.
- Власної криптографії немає.

## A05 Injection

- SQL лише з параметрами; динамічні імена колонок через список дозволених.
- Команди ОС: масив аргументів без оболонки.
- XSS: автоекранування шаблонізатора ввімкнене; `innerHTML`, `dangerouslySetInnerHTML`, `|safe`, `v-html` лише для очищеного.
- Шаблонізатор не рендерить рядки від користувача (SSTI).
- NoSQL: об'єкт-оператор із JSON не потрапляє в запит. Заголовки й логи: нові рядки відфільтровано.
- LLM: дані не виконуються як інструкції; дії обмежено кодом, а не текстом промпту.

## A06 Insecure Design

- Модель загроз існує, зокрема для зловживання бізнес-логікою.
- Обмеження частоти на вхід, відновлення пароля, дорогі операції.
- Суму, ціну, знижку рахує сервер, значення клієнта не вважаються правдою.
- Ідемпотентність платежів і незворотних дій.
- Секрети не потрапляють у контекст агента й логи.

## A07 Authentication Failures

- Захист від перебору: обмеження спроб, затримка.
- Відновлення пароля: одноразовий токен із терміном дії; відповідь не розкриває, чи існує акаунт.
- Сесія: `HttpOnly`, `Secure`, `SameSite`; оновлення ID після входу; вихід анулює.
- JWT: алгоритм зафіксовано, `none` відхиляється, термін дії короткий, підпис перевіряється.
- Багатофакторна автентифікація для адміністраторів.

## A08 Software or Data Integrity Failures

- Десеріалізація чужих даних без `pickle`, Java native serialization, `unserialize` у PHP.
- Вебхуки перевіряють підпис.
- Оновлення й артефакти підписано чи перевіряється хеш.
- CI не запускає код з форків із доступом до секретів (`pull_request_target`).

## A09 Security Logging and Alerting Failures

- Журналюються вхід, відмова, зміна прав, адмін-дії.
- У журналі немає паролів, токенів, номерів карток.
- Журнал захищено від змін; на події є сповіщення, а не лише файл.

## A10 Неправильна обробка виняткових умов

- Помилка перевірки прав закриває доступ (fail closed), а не відкриває.
- Виняток не лишає транзакцію частково застосованою.
- Вичерпання ресурсів, таймаути, неочікуваний формат мають обробку.
- Повідомлення помилки не розкриває внутрішні деталі.
