# Ідемпотентні імпорти

Ідемпотентний імпорт: повторний прогін того самого джерела дає той самий стан бази. Тоді збій посередині не страшний: запускаєш ще раз.

## Ключ джерела

Складається зі стабільних полів:

```text
source_key = "<код_джерела>:<природний_ідентифікатор>"
```

Природний ідентифікатор: номер у реєстрі, ISBN, артикул, URL, зовнішній id API. Не підходять автоінкремент, номер рядка у файлі, хеш усього рядка.

Природного ідентифікатора немає: нормалізована назва + кілька стабільних атрибутів. Запиши це рішення в опис джерела, бо воно визначає, що вважається дублем.

Унікальний індекс на ключі в базі є частиною імпорту. Без нього захист від дублів тримається лише на коді.

## Зразок upsert

```sql
-- PostgreSQL і SQLite
INSERT INTO org (source_key, name, name_source)
VALUES (:key, :name, 'auto')
ON CONFLICT (source_key) DO UPDATE
SET name = excluded.name
WHERE org.name_source = 'auto';  -- значення людини не чіпаємо
```

MySQL: `ON DUPLICATE KEY UPDATE`, умову пиши через `IF(...)`.

## Правила злиття

| Стан поля | Дія імпорту |
|---|---|
| порожнє | заповнити |
| заповнене автоматично, джерело новіше | оновити |
| введене людиною | не чіпати, додати джерело до переліку |
| конфлікт двох джерел | лишити наявне, конфлікт у звіт |

Походження поля зберігай окремо: без цього неможливо відрізнити куроване від автоматичного. Збагачені поля позначай окремо від первинних.

## Звіт

Обовʼязкова частина імпорту:

```text
прочитано  10 000
створено    8 200
оновлено    1 100
пропущено     650  (без змін)
відкинуто      50  (без ключа: 30; неправильна дата: 20)
незмаплено колонки: reg_note, old_code
```

Рівність: прочитано = створено + оновлено + пропущено + відкинуто. Не сходиться: записи зникли, імпорт не виконано.

## Тести, що ловлять найдорожче

1. **Другий прогін:** створено = 0, оновлено = 0.
2. **Часткове перезавантаження:** перервати посередині, запустити ще раз; результат той самий, що після суцільного прогону.
3. **Значення людини:** змінити поле, повторити імпорт, значення лишилось.
4. **Сміття:** порожній рядок, дублікат у файлі, неправильна дата, зайва колонка, порожній файл (порожній файл не повинен стерти дані).

## Читання джерела

- Кодування вказуй явно. Вгадане кодування псує кирилицю тихо. BOM прибирай.
- Числа й дати читай рядками, перетворюй явно: `pandas.read_csv` без `dtype` може зробити `007` числом 7.
- Excel: серійні дати і помилка з 29 лютого 1900 року, через яку рік вважається високосним. Невидимі символи (U+00A0, U+200B) в кінці значень.
- Порожнє, `0`, `N/A`, `-`: вирішуй окремо для кожної колонки й запиши правило. Невідоме лишається `null`.
- Перевір часовий пояс і формат дат: `01/02/2026` неоднозначне.

## Дедуплікація

Це окрема операція від імпорту.

1. Точні збіги за нормалізованим ключем.
2. Нечіткі збіги: блокування, щоб не порівнювати кожен із кожним, потім порівняння полів. Для великих обсягів: Splink.
3. Кандидати на злиття показуй людині з оцінкою й обома записами.
4. Злиття оборотне: зберігай, що з чого злито. Посилання інших таблиць переводь на нового власника.
5. Видалення дублів у робочій базі: Tier 3.

## Похідні структури

Після масової зміни не забудь: індекс повнотекстового пошуку, кеші, матеріалізовані подання, лічильники. Перевір 3–5 записів через те, що бачить користувач: пошук за фрагментом назви, фільтр. Запис може існувати в таблиці, але не знаходитись.

## Великі обсяги

- Порції: окрема транзакція на кожну, збереження прогресу.
- Масове завантаження (`COPY`) швидше, але вимагає проміжної таблиці для злиття.
- Порівняй час на копії перед оцінкою часу на робочій базі.
