# Прийоми код-ревʼю

Maturity: зріле (роки в індустрії), стабільне (широко вживане), молоде (ще змінюється).

1. **Ревʼю, що покращує код, а не шукає досконалість**
   - Навіщо: не блокувати зміну, яка покращує систему, і не пропускати ту, що погіршує.
   - Інструмент: стандарт Google для ревʼюера.
   - Джерело: https://google.github.io/eng-practices/review/reviewer/standard.html
   - Maturity: зріле. Безкоштовно.

2. **Що саме дивитись у зміні**
   - Навіщо: дизайн, функціональність, складність, тести, назви й документація як окремі питання.
   - Інструмент: перелік Google «What to look for».
   - Джерело: https://google.github.io/eng-practices/review/reviewer/looking-for.html
   - Maturity: зріле. Безкоштовно.

3. **Маленькі зміни**
   - Навіщо: дрібну зміну переглядають швидше й глибше, її легше відкотити.
   - Інструмент: поділ за шаром чи за кроками; порада автору.
   - Джерело: https://google.github.io/eng-practices/review/developer/small-cls.html
   - Maturity: зріле. Безкоштовно.

4. **Ліміт 200–400 рядків за раз**
   - Навіщо: за дослідженням, на яке спирається SmartBear, ефективність виявлення падає на більшому обсязі.
   - Інструмент: `git diff --stat`, поділ на порції.
   - Джерело: https://smartbear.com/learn/code-review/best-practices-for-peer-code-review/
   - Maturity: зріле, але дані вендора й старі: сприймай як орієнтир, а не як закон. Безкоштовно.

5. **Знахідка за строгою схемою**
   - Навіщо: `additionalProperties: false` не дає моделі замінити сценарій загальними словами чи загубити поле.
   - Інструмент: JSON Schema, `schemas/code-review-finding.schema.json`.
   - Джерело: https://json-schema.org/understanding-json-schema/reference/object
   - Maturity: зріле. Безкоштовно.

6. **Коментарі з міткою наміру**
   - Навіщо: автор бачить, що блокує злиття, а що є лише пропозицією.
   - Інструмент: Conventional Comments (`issue`, `suggestion`, `nitpick`, `blocking`).
   - Джерело: https://conventionalcomments.org/
   - Maturity: стабільне. Безкоштовно.

7. **Пошук дефекту правилом замість очей**
   - Навіщо: той самий клас дефекту знаходиться в усьому репозиторії, а не лише в diff.
   - Інструмент: Semgrep Community Edition; власні правила на патерн.
   - Джерело: https://semgrep.dev/docs/
   - Maturity: стабільне. Безкоштовно, розширені правила й Pro-аналіз 🔒.

8. **Семантичний аналіз потоків даних**
   - Навіщо: знаходить шлях від входу до небезпечного виклику, який не видно локально.
   - Інструмент: CodeQL.
   - Джерело: https://codeql.github.com/docs/
   - Maturity: зріле. Безкоштовно для відкритого коду; приватні репозиторії 🔒, альтернатива: Semgrep CE.

9. **Закон Гайрама як питання спростування**
   - Навіщо: видима поведінка стає контрактом, навіть коли її немає в документації.
   - Інструмент: пошук викликачів, перевірка старих клієнтів.
   - Джерело: https://www.hyrumslaw.com/
   - Maturity: зріле. Безкоштовно.

10. **Історія рядка перед оцінкою «зайвого» коду**
    - Навіщо: дивний рядок часто виправляє давній збій; `git log -L` показує, навіщо він зʼявився.
    - Інструмент: `git log -L <рядки>:<файл>`, `git blame`.
    - Джерело: https://git-scm.com/docs/git-log
    - Maturity: зріле. Безкоштовно.

11. **Семантичне версіонування як перевірка зміни API**
    - Навіщо: несумісна зміна публічного API вимагає мажорної версії, інакше ламає споживачів мовчки.
    - Інструмент: SemVer, порівняння публічних символів.
    - Джерело: https://semver.org/
    - Maturity: зріле. Безкоштовно.

12. **Безпекове ревʼю за посібником**
    - Навіщо: структуровані питання за класами вразливостей.
    - Інструмент: OWASP Code Review Guide.
    - Джерело: https://owasp.org/www-project-code-review-guide/
    - Maturity: зріле. Безкоштовно.
