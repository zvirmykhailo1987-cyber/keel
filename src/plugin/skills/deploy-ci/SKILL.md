# deploy-ci: випуск, який можна повторити й відкотити

Якщо в pre-flight сесії згадано overlay для цієї навички, прочитай його перед роботою.

## ТЗ-чекліст

«Задеплой» або «налаштуй CI» означає пакет. Веди N/N до кінця. Tier 3 пункти готуй, виконує людина.

1. Артефакт зібрано раз, версія й коміт відомі, не `latest`.
2. CI: збірка за lockfile, лінт, типи, тести, аудит, скан секретів; екшени за SHA, мінімальні права.
3. Змінні оточення описано; відсутня обовʼязкова змушує застосунок упасти при старті.
4. Бекап перед міграцією: іменований, із маніфестом, перевірений на відновлення.
5. Міграція сумісна зі старою версією коду (навичка `data-migrations`).
6. Health-check і smoke-тест є й перевіряють справжній сценарій.
7. План відкату написано, час відомий, умова запуску названа.
8. README чи ранбук оновлено, вихід із ладу теж описано.

## Pre-flight

Прочитай у `${CLAUDE_PLUGIN_ROOT}/data/pitfalls/`:

- G3 секрети; G19 бекап без маніфесту; G20 перевірка дивиться не туди; G17 вимір раніше, ніж сторінка готова.
- G11 автоматизація зареєстрована, але мертва; G50 задача падає до створення журналу; G52 тест ніде не запускається; G49 номер процесу дістався чужому.
- G7 кодування й шляхи на Windows; G42 CRLF ламає файл, а перевірка каже «здоровий»; G45 вимір у Git Bash бреше; G46 текст через heredoc приходить не байт-у-байт.
- G44 продукт живе лише на диску; G10 неповний фініш.

## Метод

### CI

1. **Збірка детермінована:** встановлення за lockfile; закріплені версії базових образів і рантайму.
2. **Послідовність:** скан секретів → лінт і типи → тести → аудит залежностей → збірка артефакту → smoke на артефакті.
3. **Екшени за SHA.** Тег можна пересунути на інший код, а повний SHA ні. Коментар із версією для читача; оновлює Renovate або Dependabot:

   ```yaml
   permissions:
     contents: read
   steps:
     - uses: actions/checkout@<40-символьний-SHA>  # vN.N.N
   ```

   Значення SHA візьми зі сторінки релізу, не вигадуй і не копіюй із памʼяті.
4. **Мінімальні права:** `permissions` на рівні воркфлоу; секрети лише на кроках, де потрібні. Для хмари OIDC замість довгоживучих ключів. Не запускай код форків із секретами (`pull_request_target` + checkout гілки).
5. **Перевір гейт:** навмисно зламаний тест чи файл із тестовим секретом роблять конвеєр червоним. Перевірка лінтером воркфлоу: `actionlint`, безпекова: `zizmor`.

### Випуск

Це план для людини. Виконання Tier 3.

1. **Передпольотна перевірка:** потрібний коміт, зелений CI, міграції прочитано, чейнджлог, хто на звʼязку, час низького навантаження.
2. **Бекап** з причиною в імені: `db_2026-11-06_pre-migration-0042`. Маніфест: що входить, розмір, хеш, час. Бекап без випробуваного відновлення не вважається бекапом.
3. **Міграція expand** перед кодом.
4. **Випуск поступово,** якщо є можливість: канарейка або blue-green; без них: у вікно малого навантаження.
5. **Дочекайся завершення випуску.** Перевірка до завершення деплою міряє стару версію. Перевір версію у відповіді застосунку.
6. **Smoke-тест** на живому: вхід, ключове читання, ключовий запис тестовим записом. Health-check «200» цього не замінює. Приклад скрипта в `references/release-runbook.md`.
7. **Спостерігай:** помилки, затримка, журнал 15–30 хвилин. Порівнюй із показниками до випуску.
8. **Умови відкату** названо заздалегідь: наприклад, частка 5xx вища за базову вдвічі протягом 5 хвилин, збій smoke.

### Відкат

- Попередній артефакт лишається доступним: відкат є перевипуском старого, без нової збірки.
- Код відкочується лише, поки схема сумісна. Міграція contract робить відкат неможливим без бекапу: тому вона йде окремим пізнішим випуском.
- Відновлення з бекапу втрачає записи після нього. Це рішення людини.
- Прапорець вимикає нову функцію швидше за перевипуск.
- Відкат перевірено хоча б раз на тестовому оточенні, час записано.

## Профіль стеку

Команди бери з `.keel/project.toml` і `${CLAUDE_PLUGIN_ROOT}/data/stacks/<id>.toml`, секція `[commands]` (test, lint, build, audit). Там само `runtime_files` для версії рантайму. Не вигадуй команд, яких немає.

Встановлення за lockfile: `npm ci` · `uv sync --locked` або `pip install --require-hashes` · `cargo build --locked` · `go mod verify` · `dotnet restore --locked-mode` · `bundle install` з `BUNDLE_FROZEN=true` · `composer install`.

Скан секретів на кроці CI і перед комітом:

```sh
sh "${CLAUDE_PLUGIN_ROOT}/hooks/run.sh" -m keel scan --staged
```

Контейнер: багатоетапна збірка; не `root`; без секретів в `ENV` чи `COPY`; build secrets для збірки; база на томі, а не в шарі контейнера. Рядки: `.gitattributes` із `*.sh text eol=lf`, інакше скрипт зламається в Linux.

## Автономія

| Дія | Tier | Хто |
|---|---|---|
| Читання конфігурації, логів CI, перевірка `actionlint`, `zizmor` | 0 | авто |
| Файли CI, Dockerfile, скрипт бекапу й smoke, ранбук на локальній гілці, локальний прогін | 1 | авто |
| Деплой, запуск міграції робочої бази, відкат, зміна конфігурації сервера | 3 | лише людина |
| Push у main, публікація пакета, ротація секретів, видалення томів чи бекапів, гроші, листи | 3 | лише людина |

Сторінка статусу й повідомлення про інцидент назовні теж за людиною.

## Типові збої

- Секрет в `ENV` образу → лишається в шарах; передавай оточенням сервера.
- `latest` чи рухомий тег → невідтворювано й небезпечно.
- База в контейнері без тому → дані зникають при оновленні.
- Бекап, який ніхто не відновлював → дізнаєшся про порожній архів під час аварії.
- Health-check міряє лише процес → застосунок живий, а база недоступна.
- Перевірка кешованої статики чи старої версії → зелено на минулому випуску.
- CI-крок проходить, бо `|| true` чи бо тестів нуль → гейт нічого не перевірив.
- Запланована задача зареєстрована, але жодного разу не відпрацювала → доказ є лише в журналі успіху.
- Скрипт із CRLF на Linux → падає мовчки чи з дивною помилкою.
- Міграція й несумісний код в одному кроці → немає можливості відкотити.

## Спростування

Назви щонайменше один сценарій, за якого випуск ламає наявну поведінку: стара версія поруч із новою під час викочування, фонові задачі зі старою чергою, кеш браузера зі старим бандлом, нова обовʼязкова змінна оточення, якої немає на сервері, цикл перезапуску, ліміт памʼяті образу. Назви й причину, чому конфігурація може не піднятись там, навіть якщо працює локально.

## Гейт «готово»

Для конвеєра:

- Запущено: посилання на прогін або локальна емуляція; `actionlint`, `zizmor`.
- Виміряно: тривалість, навмисний збій зробив його червоним, скільки екшенів не закріплено (ціль 0).

Для плану випуску:

- Сказано: що виконано (підготовка) і що ні (деплой чекає на людину).
- Відновлення бекапу й відкат прогнано чи явно сказано, що ні.
- Не перевірено: скажи явно (наприклад, smoke лише локально, образ не запускався на цільовій архітектурі).

Після випуску: версія на сервері збігається, smoke зелений, числа журналу порівняно. Не «має працювати».

## Ретро

Після випуску чи інциденту оформи урок через `/keel:retro`. Кожен ручний крок, про який забули, стає пунктом автоматичної перевірки або ранбука.
