# Захист CI

Приклади для GitHub Actions. Принципи переносяться на GitLab CI, Jenkins та інші, але назви й синтаксис там інші.

## Екшени за SHA

GitHub рекомендує закріплювати сторонні екшени за повним SHA коміту: це єдиний незмінний спосіб посилання. Тег можуть пересунути після компрометації власника екшена.

- Значення SHA бери зі сторінки релізу: `gh api repos/actions/checkout/git/ref/tags/vN.N.N` і перевір тип (`tag` потрібно розіменувати до коміту).
- Коментар із версією дозволяє Renovate й Dependabot пропонувати оновлення.
- Інструмент масового закріплення: `pinact`.
- Перевір, що SHA справді з репозиторію власника, а не форка.

Образи контейнерів закріплюй за дайджестом: `image@sha256:...`.

## Права

```yaml
permissions:
  contents: read
jobs:
  release:
    permissions:
      contents: write
      id-token: write
```

Спершу мінімум на верхньому рівні, потім окремо на завдання, що цього потребує.

## Небезпечні конструкції

| Конструкція | Ризик | Замість |
|---|---|---|
| `pull_request_target` + checkout коду PR | код форка виконується із секретами | `pull_request` без секретів, окремий воркфлоу для публікації коментарів |
| `run: echo "${{ github.event.pull_request.title }}"` | ін'єкція команди через заголовок | передай через `env:` і використовуй `"$TITLE"` |
| `${{ secrets.X }}` у `run` без потреби | потрапить у лог чи процес | лише `env` кроку, що потребує |
| `curl ... \| sh` | немає перевірки цілісності | закріплена версія й хеш |
| кеш, спільний між довіреними й недовіреними гілками | отруєння кешу | окремі ключі |
| самохостований раннер для публічного репозиторію | чужий код на твоїй машині | хмарний раннер |

Статична перевірка: `actionlint` (синтаксис і вирази), `zizmor` (безпека).

## Секрети в CI

- Хмарний доступ через OIDC замість довгоживучих ключів.
- Оточення GitHub із правилами схвалення для робочих секретів.
- Маскування логів не є гарантією: кодовані чи перетворені значення не маскуються.
- Скан секретів на кожному PR плюс pre-commit локально: два рубежі.

## Детермінованість

- Встановлення за lockfile.
- Версія рантайму закріплена й збігається з локальною (`.python-version`, `.nvmrc`, `go.mod`, `rust-toolchain.toml`).
- Той самий артефакт проходить оточення: збирається раз.
- Час, локаль, порядок файлів не впливають на вихід, якщо потрібна відтворюваність.

## Dockerfile

```dockerfile
FROM <образ>:<версія>@sha256:<дайджест> AS build
# Секрет збірки не лишається в шарі
RUN --mount=type=secret,id=npm_token sh -c 'NPM_TOKEN=$(cat /run/secrets/npm_token) npm ci'

FROM <малий-базовий>@sha256:<дайджест>
USER 1000
COPY --from=build /app /app
```

- `.dockerignore` виключає `.env`, `.git`, дампи.
- Перевір образ: Trivy.
- Базу й завантаження на томі.

## Перевірка самого гейта

Гейт CI теж потребує негативного тесту:

1. Файл із явним тестовим секретом блокується.
2. Навмисно падаючий тест робить прогін червоним.
3. Кількість зібраних тестів більша за нуль: нуль не дорівнює успіху. Pytest повертає код 5, якщо тестів немає; інші раннери поводяться по-різному, перевір свій.
4. `continue-on-error` і `|| true` тільки з коментарем і причиною.
5. Гілка main захищена: обовʼязкові перевірки, без force push.

## Метрики доставки

Чотири ключі DORA: частота розгортань, час від коміту до випуску, частка невдалих змін, час відновлення. Міряй власний тренд, а не порівнюй із чужими рівнями без контексту.
