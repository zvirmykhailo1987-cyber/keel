---
id: G50
module: core
title: Задача падає до створення логу
---
**Симптом:** панель здоровʼя зелена тижнями, а задача мертва: вона вийшла з помилкою на ранній перевірці, не створивши логу, і старий лог ще вкладається в очікуваний інтервал.
**Корінь:** джерело правди про запуск це планувальник, а не файл. Ранні гілки скрипта пишуть лише в stdout, який планувальник викидає.
**Правило:** кожен `exit ≠ 0` проходить через функцію, що пише в лог збоїв. Інтерпретатори повним шляхом (G11). Панель питає планувальника про код останнього запуску й показує збій незалежно від логу; допустимі лише коди успіху й «ще біжить» чи «ще не запускалась».
**Перевірка:** `Get-ScheduledTaskInfo <task>` дає `LastTaskResult` (у systemd `systemctl show -p ExecMainStatus <unit>`). Тест: задача зі свідомо битим шляхом до інтерпретатора робить панель червоною.
**Приклад:**
```powershell
function Fail($msg, $code) { Add-Content $failLog "$(Get-Date -f s) $msg"; exit $code }
if (-not (Test-Path $python)) { Fail "python not found: $python" 4 }
```
