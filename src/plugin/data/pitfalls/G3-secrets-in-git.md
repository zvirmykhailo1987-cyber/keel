title: Секрети в git і небезпечні дефолти
---
**Симптом:** пароль чи токен лежить у README, `.bat`, конфігу або фолбеку коду; «тимчасове» значення доїжджає до коміту, а застосунок без змінної середовища мовчки стартує зі слабким значенням.
**Корінь:** зручність першого запуску важить більше за межу між кодом і секретом. Видалення файлу не лікує витік, бо git-історія зберігає старе значення.
**Правило:** секрети лише в gitignored-файлах (`*.local.*`, `secrets.env`) плюс шаблон `.example`. Немає змінної: fail-fast, а не фолбек. Пароль людини і токен сервісу різні, щоб один витік не давав обидва доступи. Секрет потрапив у коміт: ротувати, і борг відкритий, доки ротацію не записано. Запис у `.gitignore` без ротації не є фіксом.
**Перевірка:** сканер секретів на staged у pre-commit; `git grep -nEi "(password|api[_-]?key|token)\s*=\s*['\"]"`; запуск застосунку без змінної має падати з іменем цієї змінної.
**Приклад:**
```python
token = os.environ["SERVICE_TOKEN"]            # KeyError на старті, і це правильно
token = os.environ.get("SERVICE_TOKEN", "dev") # заборонено: прод поїде з "dev"
```
