---
id: G17
module: frontend
title: Вимір раніше, ніж сторінка готова
---
**Симптом:** «0 порушень» або «все погано» з першого виклику: стилі ще вантажаться, переходи не добігли, браузер віддав стару таблицю з кешу.
**Корінь:** дію й замір зроблено в одному виклику. Перерахунок теми неатомарний: `color` уже новий, `background` ще старий. Спін-цикл блокує потік, тож CSS-перехід не рухається, а фрейм поза екраном браузер тротлить.
**Правило:** дія і замір це різні виклики. Перед вердиктом перевіряти готовність: кількість CSS-правил, очікуване значення токена теми; не збіглось, прогін викинути. Переходи вимикати на час QA, а не пережидати. Чекати на факт, а не на таймер. «Чи дійшла правка до людей» і «чи правильний CSS на диску» це різні питання: статика несе штамп версії, а фолбек штампа не може бути константою. iframe для вимірів тримати у видимій області.
**Перевірка:** `document.styleSheets[0].cssRules.length > 0` до заміру; тест, що штамп версії змінюється разом із файлом.
**Приклад:**
```js
const s = document.createElement('style');
s.textContent = '*{transition:none!important;animation:none!important}';
document.head.append(s);          // до зміни теми
document.documentElement.dataset.theme = 'dark';
await waitFor(() => tokenOf('--bg') === DARK_BG); // окремий крок, потім замір
```
