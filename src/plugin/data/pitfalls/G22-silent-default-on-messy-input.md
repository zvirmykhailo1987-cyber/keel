---
id: G22
module: core
title: Мовчазний дефолт на неохайному вході
---
**Симптом:** інструмент каже «OK», виконавши нуль перевірок, бо ключі у вході інші. Невідома категорія отримує випадкову норму. Частка `18` замість `0.18` дає абсурдний результат без помилки. Провайдер повертає 404, усе тихо йде у фолбек, а UI показує «готово».
**Корінь:** selftest калібрують на акуратних фікстурах, а `.get(key, default)` розносить проблему далі.
**Правило:** невідоме значення чи відсутній ключ дає відмову з іменем («НЕ ПЕРЕВІРЕНО: бракує полів X,Y»). «OK» дозволено лише після щонайменше однієї реальної перевірки. Одиниці мають явні межі (`0 ≤ частка ≤ 1`) з підказкою. У selftest обовʼязковий «чужий» вхід з очікуванням відмови. Конфіг переносити парами (ключ разом із моделлю). Фолбек на помилці провайдера голосний: лічильник на дашборді.
**Перевірка:** прогін на вході з чужими ключами має дати ненульовий код виходу; у звіті поле `checks_run`, і `0` є помилкою.
**Приклад:**
```python
def check(doc):
    missing = REQUIRED - doc.keys()
    if missing:
        raise ValueError(f"НЕ ПЕРЕВІРЕНО: бракує {sorted(missing)}")
```
