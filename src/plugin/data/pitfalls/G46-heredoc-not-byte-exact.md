id: G46
module: core
title: Heredoc у чужий інтерпретатор не байт-у-байт
---
**Симптом:** PowerShell here-string, переданий у `ssh … bash -s`, приносить `\r` у кінці команд (`head -6\r: invalid option`); `sed` вписує в серверний скрипт рядок із `\r`, і той ламається мовчки. `\n` у heredoc для Python стає реальним переносом.
**Корінь:** stdin не проходить через git, тому `.gitattributes` тут не діє, а кожен інтерпретатор дорогою застосовує своє трактування кінця рядка й ескейпів.
**Правило:** правки на сервері робити однорядковими ssh-командами. Якщо багаторядкове неминуче, одразу `sed -i 's/\r$//' файл`. Кожну правку shell-скрипта закривати `bash -n` на сервері. Багаторядковий Python писати `.py`-файлом або через `chr()`.
**Перевірка:** на сервері `grep -c $'\r' файл` дає 0 і `bash -n файл` без виводу. Локально на Windows лише байтами Python (див. G45).
**Приклад:**
```powershell
ssh host "sed -i 's/\r$//' /srv/backup.sh && bash -n /srv/backup.sh"
```
