---
id: G41
module: frontend
title: Парсер кольору відстає від браузера
---
**Симптом:** гейт каже «0 із N» на властивості, яку ти щойно бачив у джерелі: нуль багатошарових тіней, контраст 0 на читному тексті. Здорову тему штовхають «лагодити».
**Корінь:** Chromium віддає computed-кольори в сучасному синтаксисі без конверсії (`oklch`, `lab`, `color(srgb …)`), а регекс знає лише `rgba(...)`. Кожен новий простір це нова тиха діра. Трюк із читанням `fillStyle` не рятує.
**Правило:** нормалізувати колір не регексом, а пікселем canvas 2D: це дає RGBA числами для будь-якого валідного кольору. Шари тіней рахувати за всіма колірними функціями. Нуль на здоровому: спершу перевір парсер (G16, G21). Пари selftest ганяти до і після фікса.
**Перевірка:** `toRgba('oklch(0.5 0.1 200)')` і `toRgba('color(srgb .36 .39 .35)')` дають канали 0–255 у правильному діапазоні.
**Приклад:**
```js
const c = new OffscreenCanvas(1, 1).getContext('2d', { willReadFrequently: true });
function toRgba(css) {
  c.clearRect(0, 0, 1, 1); c.fillStyle = css; c.fillRect(0, 0, 1, 1);
  return [...c.getImageData(0, 0, 1, 1).data];
}
```
