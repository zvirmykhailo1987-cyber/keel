# Keel

Другий мозок для програміста у Claude Code. Стежить за залежностями й вразливостями, накопичує ваші уроки, веде дисципліну доставки коду й виконує лише те, що безпечно робити без людини.

**Статус: PRELIMINARY, бета.** Рушій перевірено тестами на Windows і Linux. Реальне споживання квоти, macOS і користь на великому коді ще не виміряні.

## Встановлення

Потрібні Claude Code, Python 3.11+ і git (на Windows разом із Git for Windows, він дає `sh`).

**Через GitHub (оновлення приходять самі, якщо ввімкнути автооновлення в `/plugin`):**
```
/plugin marketplace add <власник>/<репозиторій>
/plugin install keel@keel-marketplace
```

**Із ZIP:** розпакуйте архів, тоді:
```
/plugin marketplace add <шлях до теки keel-marketplace>
/plugin install keel@keel-marketplace
```

Перезапустіть сесію й виконайте `/keel:setup`, потім `/keel:init-project` у потрібному репозиторії.

## Межі автопілота

| Tier | Дії | Хто виконує |
|---|---|---|
| 0 | Звіти, скан | авто |
| 1 | Нотатки, уроки, чернетки ADR у vault, з відкатом `undo` | авто |
| 2 | Локальна гілка `keel/*` із патч-оновленням (npm, cargo, go), лише якщо ввімкнено в `.keel/project.toml` | авто, без злиття |
| 3 | Push у main, злиття, деплой, публікація, міграція робочої бази, гроші, секрети, листи | **лише людина**: виконавця в коді немає |

Вимкнено за замовчуванням: фонові LLM-кванти, планувальник, автооновлення залежностей, запуск тестів оновлених залежностей (вони виконують чужий код).

## Чесні обмеження

- **Секрет-гейт це страховка, а не межа.** Він ловить відомі формати й присвоєння та розбирає текст команди, зокрема обгортки на кшталт `sh -c`. Він не бачить скрипта з файлу чи рядка, зібраного під час виконання. Жорстку межу дає лише сервер: увімкніть GitHub push protection або gitleaks у CI.
- Локальних рубежів три: хук Claude Code (зокрема MCP-термінали й запис файлів через MCP із типовими назвами), `pre-commit` і `reference-transaction` (git 2.28+). Останній дивиться на рух гілки, тому його не вимикає `--no-verify`, і він ловить коміти без `git commit`. Якщо репозиторій уже має власні хуки чи `core.hooksPath`, Keel їх не чіпає й другий та третій рубежі не ставить. Свідомо пропустити може людина у своєму терміналі: `KEEL_ALLOW_SECRET=1 git commit --no-verify`.
- Зміну конфігу агента (`.claude/settings*.json`, `.mcp.json`, `claude mcp add`, `claude plugin install`) гейт не блокує, а питає людину. Запуск дочірнього агента без дозволів чи хуків блокує.
- Кванти розділені: той, що ходить у веб, не має файлових інструментів, а той, що читає код, не має мережі. Це прибирає очевидний канал витоку, але повної ізоляції від ін'єкцій не дає: квант із вебом усе ще бачить звіт Radar.
- Обмеження `tools` в агентах м'яке: Bash технічно може більше, ніж просить інструкція. Жорстку межу дають хуки, вузькі дозволи і відсутність виконавців Tier 3.
- Профілі стеків перевірені на маленьких прикладах: детект і команди, а не експертність у кожній мові. Swift і C/C++ мають статус `beta`.
- Maven без lockfile, C/C++ і вендорні копії Radar бачить неповно й позначає це у звіті.
- Без Git for Windows хуки не спрацюють; `/keel:doctor` це покаже.

## Діагностика й видалення

`/keel:doctor` показує реальний стан: не лише «зареєстровано», а й коли востаннє щось справді відпрацювало. Звіт не містить коду й секретів.

`/keel:uninstall` прибирає завдання планувальника й git-хуки. Vault лишається вашим.
